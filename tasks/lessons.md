# Lessons Learned

> 사용자로부터 수정 지시를 받을 때마다 여기에 기록한다.
> 세션 시작 시 반드시 이 파일을 읽고 같은 실수를 반복하지 않는다.

---

## 규칙

1. 사용자가 수정을 지시하면 → 즉시 이 파일에 패턴 추가
2. 기록 형식: `[날짜] 카테고리: 구체적 교훈`
3. 모호한 교훈 금지 → "조심하기" (X) / "fetch 대신 lib/http.ts의 httpClient 사용" (O)

---

## 교훈 목록

- [2026-11-16] 자원 범위: 연구 재료 5종과 파크 전체 자원 체계를 구분한다. 건설·사육·생산·운영의 획득처와 사용처를 먼저 연결하고, 품질 등급은 연구 재료에만 적용하는 단순한 기준안을 정리한다. 스토리·이벤트 아이템은 기본 운영의 필수 재료 수에 포함하지 않는다. 이전 '전체 재료 5종' 제한은 연구 재료 범위로 재정리한다.
- [2026-11-16] 탐험 플레이: 장소를 선택하고 해당 장소의 미션을 수행해 재료를 얻는다. 재료 5종은 각각 정해진 장소와 연결하며, 타이머 완료만으로 탐험 플레이를 완성했다고 보지 않는다. 구체적인 미션은 아직 기획 중이므로 제안·조작 예시·본게임 구현과 실제 재미 검증을 구분한다.
- [2026-11-16] 첫 합성: 파라 1마리로 시작하는 흐름을 유지하고, 첫 지정 합성은 100% 성공해 영웅 스테고케라톱스 1마리를 모두 획득한다. 첫 실패·회복 탐험은 폐기하며 반복 연구의 영웅 기본 확률과 구분한다.
- [2026-11-16] 도감 등급: 변종·하이브리드는 영웅 또는 전설에만 배치한다. 기존 희귀 하이브리드와 첫 스테고케라톱스를 영웅으로 맞추고, 도감·레시피 확률·최신 기획을 함께 갱신한다. 자연종의 기존 등급과 재료 품질 3단계를 혼동하지 않는다.
- [2026-11-15] 연구 재료: 공용 DNA를 포함한 5종·하급/중급/상급 3품질을 유지한다. 이전 5품질안은 폐기했다. 0.4에서는 일반 운영 4종을 별도 범위로 정리하며, 종별 DNA나 발광 DNA를 여섯 번째 연구 재료로 추가하지 않는다.
- [2026-11-15] 품질: 공룡의 희귀도·개체 레벨·재료 품질을 구분한다. 전설급 공룡의 최소 재료 조건은 최고 품질인 상급이며, 재료 승급으로 하위 품질을 상위 품질로 만들 수 있다.
- [2026-11-15] 합성: 레시피 원종을 실제 보유해야 시작할 수 있고, 결과 종의 희귀도가 높을수록 실패율이 높아진다. 원종 보유·DNA 재료·개체 레벨을 구분하고 전 등급 100% 성공으로 설명하지 않는다.
- [2026-11-15] 탐험: 합성에 쓰는 DNA와 촉매는 탐험으로 모은다. 정기 채취·자동 생산·스토리의 재료 즉시 지급을 탐험의 필수 과정을 대체하는 경로로 추가하지 않는다.
- [2026-11-15] 문서: 최신 기획은 docs/current, 구버전은 원자료, 실제 구현은 TASK·코드로 구분한다. 문서 내부의 과거 버전 번호나 기획에 적힌 기능을 최신 구현 완료로 취급하지 않는다.
- [2026-11-15] 수집: 공룡 획득에는 탐험·부화뿐 아니라 DNA 합성으로 만드는 변종·하이브리드가 포함된다. 기존 도감의 원종 조합과 스토리 3-6 첫 스테고케라톱스를 확인하고 경로를 설계한다.
- [2026-11-15] 밸런스: 신규 시작 자금 감액은 입장료·첫 시설·탐험 연결과 함께 적용한다. 현재 게임의 기존 계정 잔액·공용 DNA를 새 기획값으로 덮어쓰지 않는다.
- [2026-11-15] 경제: 매출의 원천은 방문객 입장료다. 공룡의 종류·인기도·행복도는 방문 수요와 관람 만족도에 영향을 주며 공룡별 직접 골드 생산으로 설명하거나 구현하지 않는다.
- [2026-11-15] 파크: 공원 외곽 테두리와 서식지 울타리를 구분한다. 기존 공룡·서식지·입구 SVG를 우선 활용하고, 필요한 경계·길·방문객·시설 요소만 보충한다.
- [2026-11-15] 검증: 서버 lint에 포함되는 test 폴더는 별도 tsconfig.eslint.json의 include에 연결한다. 규칙을 끄거나 검사 대상을 숨기는 방식으로 통과시키지 않는다.
- [2026-11-15] 스토리: 도입부는 상세 시나리오와 현재 game-data의 '편지를 받고 15년간 버려진 파크를 재건' 설정으로 통일하며, GDD의 표류 설정을 재사용하지 않는다.
- [2026-02-05] 타입: shared types의 position 필드는 Prisma 스키마 기준 positionX/positionY 사용
- [2026-02-05] 보안: IAP 영수증 검증은 프로덕션에서 반드시 실제 검증 구현 필요 (항상 true 금지)
- [2026-02-05] 동시성: 재화 차감은 반드시 $transaction 안에서 atomic하게 처리
- [2026-02-05] 빌드: game-data에서 balance와 shop 모듈 간 export 이름 충돌 주의
- [2026-02-05] 밸런스: DINOSAUR_STATUS.maxIntimacy는 1000 (100이 아님)

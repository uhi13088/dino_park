# 기획 문서 안내

문서 체계 정리: 2026-11-17. **최신 기획은 `current/`부터 읽는다.** 기획 버전 `0.6`는 재정비 문서의 버전이며, 앱의 출시 버전이나 구현 완료를 뜻하지 않는다.

## 페이지형 통합 가이드북

열람과 편집은 **[Word 가이드북](guidebook/output/dino-park-guidebook.docx)**을 기준으로 한다. 탐색 창에는 장과 핵심 제목을 두고, 본문 2쪽에는 장 목차, 3쪽에는 빠른 찾기를 둔다. 개별 항목은 장 안내와 이름 색인에서 찾는다. [인쇄용 PDF](guidebook/output/dino-park-guidebook.pdf)와 [갱신 절차](guidebook/README.md)를 함께 제공한다. 기획을 바꿀 때는 아래 담당 원천을 수정하고 같은 작업에서 가이드북을 갱신한다.

## 현재 플레이 목표

장기간 파크를 계속 운영하고 확장하는 게임이 현재 목표다. 앱인토스는 초기 플랫폼 검토 배경으로 구분한다. 접속 시간을 짧게 제한하거나 접속당 목표 하나만 진행하도록 정한 요구는 없다. 후반 건설·연구의 장기 타이머와 운영·탐험·수집의 병행이 성장 구조다. 첫 합성 경과4~6시간은 초반 검산 기준안이며 전체 게임의 플레이 길이나 접속 주기와 구별한다.

## 읽는 순서와 원천

2. [기본 자원·생산 0.6](current/resources-and-production.md): 재료별 필요성·종류·품질·생산/획득·사용처·통합/후속 범위. **자원 체계는 이 문서가 원천**이다.
3. [운영·생산·초반 밸런스 0.6](current/balance.md): 입장료 공식, 구매·생산·시설·미션·승급의 수량·비용·시간과 검산. **경제 수치는 이 문서가 원천**이다. 25레벨·금고/연료 검산과 과거0.4 첫 성장 모델, 실제 구현 검증을 구별한다.
4. [공룡 획득·DNA 연구 0.6](current/dna-and-collection.md): 탐험, 변종, 하이브리드, 레시피와 해금. **개별 합성 레시피의 재료·제작비·연구 시간은 이 문서가 원천**이다.
5. [건물 역할·25레벨 기획](current/buildings.md): 주요21종의 성장/외형과 기존52종 역할·통합·도입 순서. 수치는 밸런스 원천을 따른다.
6. [건물별 전 단계 표](current/building-upgrade-tables.md): 골드·목재·석재·금속·시간·유지비·효과525행과 시설별 누적 투자. 생성 모델은 입력을 밸런스에서 읽는다.
7. [기술 연구트리](current/research-trees.md): 4계열72항목·각3~5단계·선행·효과·연구원 역할. **기술 항목·선행과 기존14개 효과는 이 문서, 신규58개 효과는 하위 [효과 상세](current/research-effects.md), 비용/시간은 밸런스가 원천**이다. DNA 합성은 별도 작업이다.
8. [연구별 자원·시간 전체표](current/research-cost-tables.md):72항목별총252회연구의골드/목재/석재/금속·기본시간/최종하한. 밸런스원천의파생표다.
9. [나머지58개 연구 효과](current/research-effects.md):194레벨의 수치·대상종·지역/미션·적용/중첩과 준비 조건의 정본. **[읽기용 레벨별 효과표](current/research-effect-tables.md)**는 이 정본에서 생성한다.
10. [탐험 플레이](current/exploration-play.md): 육상 차량·해상 보트 주행, 자유 좌우 조작, 난도·회수량 증가, 재료·지정 알 목표와 재개·단일 수령 규칙. 준비비와 부화 조건은 밸런스, 미션 권한과 보상은 연구 효과 원천을 참조한다.
11. [확장·미션·합성 상세표](current/followup-content-tables.md):토지5단계·특수5시설125행·재료46미션·알51목표·후속9+공개보완1레시피·계획83종 호환의 읽기용 생성표.
12. [초반 스토리 진행과 대본](current/story-progression.md): 프롤로그부터3-6 첫 합성까지18장면의 최신 대사·장면별 진입/완료·플레이 목표·보상/해금 연결. 4장부터 에필로그의17장면은 실제 시설·연구·탐험 조건과 연결한다. 사이드·시즌의 추가 실행 조건은 후속이다.
13. [스토리·등장인물 통합 기획](current/story-and-characters.md): 세계관·본편·사이드·4시즌과 등장인물의 일관된 설정. 아서는 마지막 여정과 유산을 남긴다.
14. [위인 통합 기획](current/great-figures.md): 위인50명·GP 영입/수급·Lv.1~10 능력·보유/배정·관계/분류 시너지와 중첩 상한. 수치 기준안과 현재 구현을 구분한다.
15. [제작·서비스 통합 기획](current/production-and-services.md): 아트·사운드·시즌 운영·소셜·상점·품질 기준.
16. [83종 획득 정본](current/dinosaur-acquisition.md)·[전체 획득표](current/dinosaur-acquisition-tables.md): 모든 종의 최초/반복 경로·해금·비용·부화/합성·전시. 기존51알목표+보완17=68종 반복, 첫 랩터 예외1, 기존13+변종2=15합성을 통합한다.

요약 문서에 다른 수치를 추가하지 않는다. 구현 시 수치는 기존 `shared`·`game-data`의 소유 위치에 반영하고 서버와 클라이언트가 함께 참조한다. 문서용 새 설정을 런타임 설정과 병행 운영하지 않는다.

## 이전 최신 기획 보관

[0.2 보관본](archive/0.2/game-design.md)은 2026-11-15의 변경 전 기준이다. 종별 DNA·정기 채취·확정 성공은 0.3에서 폐기했다. 보관본은 구현 기준으로 사용하지 않는다.

[0.3 보관본](archive/0.3/game-design.md)은 2026-11-16 자원 재정리 직전 기준이다. 전체 재료 5종·골드 전용 건설·대기형 탐험은 0.4에서 일반 4종+연구 5종·자재 건설·장소별 플레이 미션으로 재정리한다. 과거 검산 시간을 새 구조의 검증 결과로 사용하지 않는다.

[0.4 보관본](archive/0.4/game-design.md)은 주요25레벨·전체금고·탐험연료 재정비 전 기록이다. 최대5단계 제안은0.5에서 주요25레벨로 변경했다. 0.4 설계 모델은 보관된 입력을 읽으며 현재0.5의 실제 플레이 시간 증거로 사용하지 않는다.

[0.5 보관본](archive/0.5/game-design.md)은 연구 중심 성장/72항목 확장 직전 기준이다. 12기술총48회 연구 수치·초기1분/후기7일·연구원초기1명/다이아추가구매를 보존한다. 0.6은4계열72기술총252회연구의목적/선행과자원/시간을설정한기획이다. 72항목252회 연구의 레벨별 효과도 정의했으며 실제 전체 수급/기간은 미검증이다. 기존0.5 모델은 보관 입력, 새0.6 모델은 current 입력을 읽는다.

## 충돌 정리

| 항목 | 최신 기준 |
| --- | --- |
| 표류해서 새 파크 건설 / 폐쇄된 파크 재건 | 편지를 받고 15년간 버려진 파크를 재건 |

| 시작 골드·관람대 가격 | [밸런스 0.6](current/balance.md)의 검산/적용 상태 확인. 현재 코드값·새 초반 수치안·후반 미정 수치를 구별 |
| 탐험만으로 공룡 획득 | 탐험·부화와 DNA 합성 두 경로. 변종도 연구 목표에 포함 |
| 구버전 밸런스의 스피노렉스·스텔스 랩터 등 | 이번 레시피에서 제외. 도감·스토리와 맞는 종부터 사용 |
| 재료 종류·품질 | 일반 4종(무품질)+연구 5종(하급·중급·상급)=기본 소모품 9종·재고 조합 19개. GP는 위인 영입 전용 재화로 별도 분류 |
| 자원 생산·사용 | 일반4종은 골드 구매/시설 생산으로 건설·급식, 연구5종은 장소별 미션으로 합성에 사용. 탐험 연료는 기존 에너지 단일 재고의 공급 확장이며 일반 재료에 추가하지 않음 |
| 골드/누적 입장료 | 보유 골드는 금고 한도, 누적 입장료는 실제 받은 평생 실적. 별도 예금/이자 없음, 기존 초과분 보존 |

## 변경 규칙

- 같은 주제를 수정할 때 `current/`의 담당 문서를 고치고 TASK에 남긴다. 새 초안을 기존 문서 끝에 계속 덧붙이지 않는다.
- 작은 수정은 최신 문서의 변경 기록에 남긴다. 핵심 루프가 바뀌면 다음 기획 버전을 만들고 이전 기준의 보관 시점을 명시한다.
- 구버전 원자료에서 규칙을 가져오려면 최신 문서에 승계 범위와 충돌 해결을 먼저 적는다.
- `current/`에 없는 장기 콘텐츠는 재검토 대상이다. 구버전 전체를 묵시적으로 최신으로 승격하지 않는다.

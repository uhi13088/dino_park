# 다이노 파크 기획 가이드북 관리

**[다이노 파크 플레이 가이드 Word](output/dino-park-guidebook.docx)**를 플레이어 안내의 기준으로 사용한다. [PDF](output/dino-park-guidebook.pdf)는 Word에서 생성한 인쇄용 사본이다. 플레이어가 기능을 어디에서 만나고 어떤 순서로 이용하는지 설명한다. 작업 순서·구현 검증·제작 문서는 저장소의 담당 원천과 기록에서 관리한다. Word 탐색 창, 목차, 빠른 찾기, 이름 색인으로 각 항목에 이동할 수 있다. 파일명은 다음 판에서도 유지한다.

## 작업 위치와 원천

- `docs/current/`: 최신 게임 규칙과 수치의 담당 원천. 가이드북에서 별도 규칙을 만들지 않는다.
- `docs/current/production-direction.md`: 현재 제작의 완료 기준과 리더·재건 목표·거래의 합의 및 후속 제안. 구현 우선순위는 TASK.md와 함께 갱신한다.
- `docs/current/dinosaur-acquisition.md`·`dinosaur-acquisition-tables.md`: 공룡83종의 최초/반복 경로와 전체 조회표. 알68종의 반복목표·첫 랩터 예외1·합성15종을 연결한다. 새 종/레시피/권한을 바꾸면 이 표와 개별 도감도 같은 작업에서 갱신한다.
- `docs/current/park-progression.md`·`park-progression-tables.md`: 첫 영웅 이후 Park5~50의45레벨 전환·180개 일회성 성장목표/XP. 시설·연구·획득의 기존 권한과 비용을 참조하고 별도 실행 설정을 만들지 않는다.
- `docs/current/operation-balance.md`: 첫 7일과 파크 Lv.15·25·35·50의 수급 검산과 복구 초안. 비용이나 해금을 바꾼 뒤에는 `python3 docs/models/render_operation_balance_v06.py --write`로 수급표를 갱신한다.
- `docs/current/story-progression.md`: 프롤로그~3장18장면의 최신 대본과 플레이 연결, 이후17장면의 시설·연구·탐험·본편 완료 조건. 해당 장면은 이 정본을 직접 수록하고 구버전 요약을 중복된 실행 기준으로 쓰지 않는다.
- `docs/guidebook/content.py`: 원천을 읽어 장·항목·페이지를 구성하는 표시 코드.
- `docs/guidebook/editorial/`: 스토리·인물·위인·후속 참고의 출처 있는 편집 요약. 구버전 참고와 실제 코드 관찰을 구분한다.
- `docs/guidebook/output/`: 최종 PDF·Word. 직접 고친 내용을 유지하려면 기획 원천 또는 편집 요약에도 반영한다.
- `docs/guidebook/manifest.json`: 입력 파일과 출력의 지문, 페이지·색인·커버 범위. 생성되며 직접 편집하지 않는다.
- `tmp/guidebook/`: 렌더 이미지·페이지 계획·검사 결과. 열람용 최종 파일과 구분한다.

## 기획이 바뀌었을 때

1. 해당 원천에서 규칙·숫자·이름·구현 상태를 수정한다. 기존 파생표는 담당 모델로 다시 생성한다.
2. 편집 요약의 출처가 바뀌었다면 변경 내용을 읽고 요약과 `source_sha256`을 함께 갱신한다. 출처 지문만 덮어써 오래된 요약을 통과시키지 않는다.
3. 프로젝트 루트에서 다음 명령으로 PDF·Word·목차·색인을 함께 다시 만든다.

```bash
bash docs/guidebook/update_guidebook.sh
```

4. 생성된 페이지를 검토하고 내용·쪽수·이동 링크·글자·표를 검사한다. 이전에 검토한 페이지와 PNG 지문이 같다면 해당 검토를 재사용할 수 있고, 달라진 페이지는 다시 확인한다.
5. 완료 기록까지 정리한 뒤 최신성 검사를 통과시킨다.

```bash
bash docs/guidebook/update_guidebook.sh --check
```

`--check`는 출력이 최신 원천과 연결되어 있는지 검사한다. 오래된 원천/편집 요약, 빠진 입력, 출력 파일의 임의 변경이 있으면 실패한다. 책을 다시 내보내기만 하고 요약 내용은 오래된 상태인 경우도 통과하지 않는다.

## 열람과 편집 원칙

- 2쪽 목차에는 12장 시작점을 한 페이지에 표시한다. 3쪽 빠른 찾기에는 성장표·건물 강화표·연구·레시피처럼 자주 찾는 항목을 모은다. 두 페이지 모두 항목 이름과 쪽수를 본문 북마크에 연결한다.
- Word 탐색 창은 목차·빠른 찾기·색인과 12장 및 핵심 제목으로 구성한다. 이어지는 페이지의 제목, 개별 레벨 및 도감 카드의 제목은 본문 서식으로 표시하고 장 안내와 색인에서 이동할 수 있게 북마크를 둔다.
- 각 장 첫머리는 해당 분야의 분류별 안내다. 건물 강화표·4계열 연구·합성 레시피·등급별 공룡은 여기서 이름을 골라 상세로 이동한다. 장이나 항목을 되찾을 때는 Word 탐색 창과 바닥글의 목차·색인을 사용한다.
- 이름 색인은 공룡·인물·위인·연구·건물·재료를 직접 찾을 때 사용한다. 같은 이름은 분야와 현재 ID로 구별한다. PDF 북마크도 Word의 장·핵심 제목 구조를 따른다.
- 검증에는 첫 합성·재료 수량·연구원 고용·건물 강화·공룡 이름·주행·경기 등 실제 플레이 질문에서 출발해 목차·장 안내·색인으로 해당 본문을 찾는 과정이 포함된다.
- 도감은 공룡83종과 위인50명을 수록한다. 플레이 가이드는 완성 게임의 흐름을 설명하며 실제 적용과 검증은 TASK에서 확인한다.
- 83종 획득표·개별 도감의 최초/반복 안내·알목표·15레시피는 획득 모델과 공통 표시 함수를 사용한다. 오래된 `unlockCondition.description`을 계획상 획득 경로로 대신 쓰지 않는다. 표의83행·도감166획득문단·부모 경로·실제Word 전사는 `check_guidebook.py`에서 검증한다.
- 성장표는 원천180목표→페이지 계획→실제Word의 조건/XP를 대조한다. 빠른 찾기에는 전체 공급표, 장 안내에는 5레벨 구간, 이름 색인에는 개별 Park를 둔다. 180목표를 앞목차에 펼치지 않는다.
- 위인 GP·보유/배정·성장·시너지의 현행 기준은 `docs/current/great-figures.md`다. 폐기된 직접 골드 수익·옛 점유·합성확률 버프를 새 통합 기획에 섞지 않는다.
- 사용자 결정과 최신 기획이 원천보다 우선한다. 충돌은 ‘정리 필요’로 남기고 임의로 합치지 않는다.
- Word에서 합의한 기획 수정은 담당 원천에도 반영해 다음 판에 유지한다. 목차·빠른 찾기·장 안내·색인의 쪽수는 렌더에서 북마크가 실제 위치한 쪽을 읽어 갱신한다. 내부 이동은 위치가 바뀌어도 Word 북마크를 따른다.

## 생성 환경

현재 Codex에 포함된 Python·python-docx·LibreOffice·Poppler를 사용한다. 실행 스크립트는 패키지를 자동 설치하지 않는다. 한글 출력에는 이 Mac의 Apple SD Gothic Neo를 사용하며 PDF에 글꼴을 포함한다. Word의 편집 환경이나 글꼴이 바뀌면 재배치될 수 있으므로 배포 전 PDF를 다시 확인한다.

문서 제작 코드나 형식을 바꾼 경우에도 페이지/링크/색인 검사를 다시 수행한다. 가이드북은 GitHub·클라우드에 자동 게시하지 않는다.

## 지면 디자인 유지

- A4 판형과 한글 본문 10.5pt/줄간격 15pt, 장 제목 23pt, 표 9.5pt를 기준으로 한다. 표지·목차·빠른 찾기 이후 본문과 색인은 연속 배치한다. 짧은 항목마다 쪽을 강제로 바꾸거나 이어지는 쪽에 제목을 반복하지 않는다.
- 대본은 화자를 굵게, 장면 ID는 보조 정보로 표시한다. 공룡 프로필은 개체별 제목과 정보를 함께 읽을 수 있게 묶는다. 연구 상세는 효과와 비용표의 구성을 통일한다. 긴 표는 행 사이에서 넘어가고 새 쪽에서 머리행을 반복한다.
- 수치표는 짙은 청회색 머리행과 옅은 교차 행을 사용한다. 건물 표의 5/10/15/20/25레벨은 성장 구간으로 강조하며, 자재 순서와 단위를 함께 안내한다.
- 표지 그림은 기존 임시 에셋 6개를 합성한 것으로 최종 아트가 아니다. 생성 명령은 번들 Node로 `docs/guidebook/create_cover_art.mjs`를 먼저 실행하므로 원본 SVG 변경도 다음 책 생성에 반영한다. 산출 그림과 스크립트도 입력 지문에 포함한다.
- 장식보다 읽기와 탐색을 우선한다. 새로운 표시 서식도 렌더로 확인하고 목차·색인·링크·페이지 검사를 통과해야 한다.

## 통합 기획 원칙

본문에는 각 주제의 현재 기획 한 벌만 수록한다. 과거/현재의 병렬 줄거리·구버전 별도 장·충돌 나열 표로 통합을 대신하지 않는다. 사용자 확정 사항을 우선해 설정·역할·수치의 충돌을 해결하고, 새 결정이 필요한 항목만 구체적으로 명시한다. 출처·이력은 원천/manifest로 추적하며 본문은 읽을 수 있는 통합 설명으로 쓴다.

스토리와 시즌은 story-and-characters, 초반 대사/목표는 story-progression, 위인 수치는 great-figures, 제작·서비스는 production-and-services가 소유한다. GP는 위인 영입, 다이아는 일반 연구원 추가 구매에 사용한다. 위인50명의500레벨 표와 보유/배정·관계/분류 효과를 같은 원천에서 생성한다.

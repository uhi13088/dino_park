## 1. 화면과 아트 방향

화면은 아이소메트릭 파크와 읽기 쉬운 목록·상세를 연결한다. 녹색 파크, 둥근 카툰 공룡, 밝은 면과 정돈된 윤곽을 사용해 친근함과 공룡의 경이로움을 표현한다. 과도한 세부 묘사와 반복 장식은 줄이고 공룡·시설·길의 실루엣을 분명하게 나눈다.

파크 화면은 개장 상태와 주요 재화, 현재 목표, 건설·탐험·도감 진입을 제공한다. 경계·입구·방문객 길·서식지 울타리를 구별하고, 시설 배치는 미리보기·비용 확인·확정·취소로 끝낸다. 장기 건설·연구 중에도 운영·탐험·수집 화면을 오갈 수 있게 한다.

도감은 검색·등급·획득 분류와 수집·현재 보유·계보를 함께 보여준다. 진한 녹색 글자, 옅은 녹색 바탕과 흰 읽기 면을 사용하며 등급과 보유 상태를 글자로도 전달한다. 도감의 세부 토큰은 DESIGN.md를 따르고 파크 화면에는 공간 조작에 맞는 배치를 사용한다.

모바일과 넓은 화면에서 핵심 조작과 읽기 순서를 유지한다. 선택한 항목의 제목과 복귀 위치를 보존하고 키보드 초점·로딩·빈 결과·오류·재시도를 표시한다. 공사·부화·기술 연구·DNA 합성의 진행과 수령 상태를 구별하며, 비용·효과·시간은 각 담당 기획의 값을 읽는다.

| 화면 묶음 | 주요 행동 | 반드시 보여줄 정보 |
| --- | --- | --- |
| 메인 파크 | 관찰·배치·돌봄·개장과 시설 이동 | 외곽 경계·길·관람 가능 상태, 입장료와 금고 한도 |
| 도감과 상세 | 검색·분류·개체와 계보 확인 | 수집과 현재 보유, 획득 경로, 실제 원종 보유 조건 |
| 탐험 | 장소·목표 선택, 조사와 결과 수령 | 준비비·단일 연료·미션 체크포인트·보상 |
| 건설과 연구 | 비용 확인, 작업 시작과 완료 확인 | 유휴 인력·선행 조건·완료 시각·적용 효과 |
| 스토리와 인물 | 대화·선택지·인물 기록 열람 | 현재 장면·선택 기록·다음 플레이 목표 |
| 상점과 위인 | 상품 또는 위인 선택과 최종 확인 | 구매 재화·영입 GP·조건·중복 보유와 지급 결과 |

## 2. 음악과 사운드 제작

사운드는 섬의 몰입감, 공룡과 인물에 대한 정서적 연결, 행동에 대한 명확한 피드백과 편안한 장시간 청취를 목표로 한다. 평상시 파크·초식 구역·밤과 해변은 평화롭게, 안전 위기와 이야기의 절정은 긴장감 있게 구분한다.

음악은 오케스트라를 중심으로 전자음과 월드 악기 색채를 섞는다. 현악은 감정선, 목관은 자연의 신비, 금관과 타악은 장엄함과 위기, 패드와 가벼운 플럭은 몽환적이거나 귀여운 순간을 맡는다. 같은 주제 선율을 발견·재건·이별·계승 장면에서 변주한다.

장소·시간대·활동에 맞춰 음악 층과 환경음을 전환하고 급격한 단절을 피한다. 중요한 대사에는 음악과 환경음을 낮추는 덕킹을 적용한다. 인물 보이스와 컷신은 스토리와 등장인물 정본의 성격·관계·시점을 따르며 기록 음성과 현재 대사를 구별한다.

음악·효과음·보이스의 음량과 음소거를 각각 조절한다. 반복 울음과 획득음은 겹침과 빈도를 제한하고, 무음 상태에서도 성공·오류·위기를 글자와 화면으로 전달한다. 오디오는 루프 경계·전환·동시 재생·압축 손실을 실제 재생 환경에서 검수하고 대상 ID별 제작 목록으로 관리한다.

| 분류 | 제작 방향 | 검수 기준 |
| --- | --- | --- |
| 메인과 장소 BGM | 파크의 일상·시간대·지역 분위기 | 긴 청취의 피로, 반복 경계와 장면 전환 |
| 스토리 BGM | 발견·감동·위기·이별과 계승 | 대사 전달과 장면의 감정 흐름 |
| 공룡 효과음 | 종·크기별 울음, 대기·기쁨·배고픔·이동·섭식 | 서로 다른 실루엣에 맞는 음색, 과도한 중첩 방지 |
| 환경음 | 바람·물·숲·해변과 구역의 생활감 | 거리와 실내·실외·수중의 구분 |
| UI와 게임 피드백 | 선택·확인·획득·건설·돌봄의 반응 | 동작 결과 구분과 시각 피드백 병행 |
| 보이스와 믹싱 | 인물별 어조, 기록 음성, 덕킹 | 정본 관계·시점과 음량 균형 |

## 3. 에셋 제작과 파일 기준

제작 명세는 공통 스타일에 대상의 특징·상태·포즈·크기를 조합한다. 공룡은 대기·이동·섭식·수면·초상, 인물은 초상·전신·감정, 시설은 역할과 강화 구간의 외형으로 나눈다. 파일과 스프라이트에는 대상 ID·상태·크기·프레임 정보를 연결하고 투명 배경과 바닥 기준점을 유지한다.

초기 SVG의 실루엣과 배치 기준점을 작업용 참고로 쓴다. 배포용 파크 오브젝트는 아이소메트릭 시점과 공통 조명을 적용한 2.5D 래스터 스프라이트다. 투명 PNG를 원본으로 관리하고, 배포 용량을 줄일 때 알파 채널을 보존하는 WebP를 사용한다. 같은 건물의 단계별 그림은 바닥 기준점과 점유 영역을 맞춘다.

### 플레이 흐름별 제작 순서

1. 플레이할 흐름을 따라가며 새 그림이 필요한 화면과 상태를 적는다. 이미 같은 용도로 쓸 수 있는 이미지를 확인하고 필요한 것만 제작 목록에 올린다.
2. 같은 종류의 실제 게임 이미지를 기준으로 고른다. 시설은 아래 관람대 묶음의 카메라와 조명을 참고한다. [구버전 프롬프트 자료](../assets/dino_park_asset_main.md)에서는 대상별 특징을 찾는다.
3. 제작 요청에는 대상 ID, 사용 화면과 상태, 기준 이미지, 화면 표시 크기와 원본 해상도, 배치 방향·바닥 기준점·점유 칸, 투명 PNG 원본과 배포용 WebP의 파일명을 적는다.
4. 실제 게임에 시험 배치한다. 타일과의 정렬, 앞뒤 가림, 모바일 축소, 조명과 실루엣, 강화 전후 상태를 확인한다.
5. 검수를 마친 파일을 정해진 경로와 에셋 매핑에 등록하고 대상 ID에 연결한다. 공통 표현이 안정된 뒤 같은 계열의 레벨과 포즈를 묶어 제작한다.

첫 비교 묶음은 2:1 파크 격자의 같은 부지에 두는 관람대다. Lv.1~4는 개방형, Lv.5는 넓은 청록색 지붕을 사용한다. 배포 파일은 `apps/client/public/assets/buildings`의 `viewing-platform.webp`와 `viewing-platform-lv5.webp`다.

기본 제작 대상은 계획 공룡83종, 건물 카탈로그52항목, 기본 위인50명이다. 같은 인물·종의 변형과 시즌 연출은 ID에 연결하고 별도 수집 항목을 만들 때만 분모를 변경한다. 종별 실루엣·성별 또는 연령 표현·의상·음색·상태별 납품물은 제작 목록에서 관리하며 목록의 목표 수와 납품 파일 수를 구별한다.

시설은 Lv.5·10·15·20·25의 큰 변화를 같은 건물로 인식할 수 있게 표현한다. 스킨은 외형 변형이며 게임 효과는 별도 담당 규칙을 따른다. 시각적 크기나 프롬프트 문구로 수용량·물리 점유·수익·합성 능력을 정하지 않는다. 컷신·초상·보이스의 인물 나이와 관계는 스토리와 등장인물 정본을 따른다.

| 제작 분야 | 필수 제작 정보 | 파일·교체 기준 |
| --- | --- | --- |
| 공통 스타일 | 부드러운 셀 셰이딩, 아이소메트릭 시점과 조명 | 대상 ID·상태·크기·투명 배경·접지 위치 |
| 공룡 | 종별 실루엣, 대기·이동·섭식·수면·초상 | 계보와 등급을 식별하고 종별 경로에 연결 |
| 건물과 인물 | 시설 역할, 직업과 연령, 초상·감정 | 같은 건물·인물 ID의 상태와 외형으로 관리 |
| 컷신 | 현재 장면의 장소·등장인물·감정과 시점 | 스토리 장면 ID에 연결, 기록·회상 표현 구분 |
| 아이템과 환경 | 기본 재료·재화 아이콘, 타일·자연물 | 9종 재료와 별도 재화를 구별하고 용도를 표시 |
| 기믹과 스킨 | 탐험 단서, 외형 변형과 꾸미기 | 현재 미션 동작과 외형을 연결, 효과 수치 복제 금지 |
| 업그레이드 외형 | 주요 5레벨 구간의 실루엣 변화 | 건물 레벨과 실제 점유·수용량 규칙 유지 |
| 2.5D 맵 스프라이트 | 건물·공룡·소품의 아이소메트릭 표현 | 투명 PNG 원본과 배포용 파일, 공통 광원과 바닥 기준점 |

## 4. 시즌 운영과 이벤트

시즌은 본편 이후에도 같은 파크를 운영하며 이야기·탐험·수집 목표를 확장하는 방식이다. 네 시즌의 이름·등장인물·다섯 장씩 총20장의 줄거리는 스토리와 등장인물 정본이 소유한다. 이 절은 공개·목표 진행·보상·종료 처리를 담당한다.

시즌의 시작과 종료, 대상 플레이어, 목표, 보상, 수령 기한을 한 안내에서 확인하게 한다. 오프닝은 새 이야기를 소개하고, 공동 탐험·퀴즈·기록 수집·복원 공사·피날레는 평소의 파크 운영과 연결한다. 공동 목표는 실제 기여를 기록하며 재접속이나 같은 요청으로 기여와 보상을 중복 처리하지 않는다.

시즌 패스는 스토리·일일·주간·시즌 목표의 진행을 한 화면에서 연결하고 무료·선택 유료 트랙의 보상을 구분한다. 결제 없이도 본편의 필수 성장과 첫 지정 합성에 도달할 수 있게 한다. 패스 진행은 미션과 보상 이력에 따라 기록하며 달력의 경과만으로 미완료 플레이를 완료하지 않는다.

일지·기억·에덴의 핵 등 이야기 소품은 장면 진행 기록으로 관리한다. 시즌 진행 포인트와 이벤트 교환 물품은 기본 소모 재료9종·위인 영입 GP와 분리한다. 보상에 알이나 재료를 사용할 때는 기존 획득 조건·품질·보유·한도를 명시하고, 시즌 종료가 파크·수집·진행 중 작업을 초기화하지 않게 한다.

| 운영 단계 | 플레이와 안내 | 진행·보상 처리 |
| --- | --- | --- |
| 시작 안내 | 시즌 목표·대상·시작과 종료·수령 기한 제시 | 플레이 조건과 보상을 공개 전에 함께 고정 |
| 이야기 공개 | 정본의 시즌 장면을 순서대로 제공 | 장면 ID와 완료 기록, 플레이 목표 연결 |
| 공동 탐험과 복원 | 개별 기여를 공동 목표에 누적 | 기여·지급의 중복 방지와 개인 진행 보존 |
| 시즌 패스 | 무료·선택 유료 트랙의 목표와 보상 확인 | 구매 상태·완료 목표·수령 이력을 구별 |
| 피날레와 종료 | 최종 목표와 남은 보상 안내 | 기한 처리 후에도 파크와 영구 수집 기록 보존 |

## 5. 시즌 생물과 인물 제작 목표

기본 수집 목표는 공룡83종과 위인50명으로 유지한다. 아래 생물20개 이름과 인물12명의 시즌 제작 대상은 확장용 목록이며, 같은 인물이나 종을 본편 분모에 중복 합산하지 않는다. 메갈로돈 자연종과 메갈로돈 알파처럼 별도 개체·외형을 구별하고, 정본이 같은 대상으로 정한 항목은 하나의 ID에 연결한다.

생물은 시즌 환경에 맞는 외형·서식 조건·알 또는 획득 목표·돌봄·전시를 함께 제작한다. 일반 수집에 추가하려면 등급·획득 경로·서식지·재료나 레시피의 담당 명세를 먼저 갖춘다. 이름이나 컷신 등장만으로 소유 공룡을 지급하거나 합성 레시피를 만들지 않는다.

인물은 스토리와 등장인물 정본의 관계·연령·시간 순서를 따른다. 엘리자베스 우는60대 연구자이며 진의 스승이다. 아서 해먼드는 시즌1 마지막 여정 이후 유산 기록으로 제작하며 살아 있는 영입 직원으로 되돌리지 않는다. 기본50명의 동일 ID 기록 수집과 GP 조건·효과는 위인 기획이 소유한다.

시즌의 특수 외형과 연출을 기본 수익·합성 성공률·첫100%·재료 조건·후기 연구 최종하한을 바꾸는 효과로 해석하지 않는다. 위인 배정 가능 여부와 능력은 위인 기획을, 공룡의 자연종·변종·하이브리드 분류와 합성은 DNA 기획을 따른다.

## 6. 친구 방문과 교류

친구를 검색해 요청·수락한 뒤 파크를 방문하고, 공룡과 교감하거나 좋아요·댓글을 남기며 선물을 주고받는다. 관계 관리에는 요청 취소·거절·친구 해제와 차단을 포함하고, 방문 화면은 주인의 파크를 관찰하는 상태와 내 파크 편집을 구별한다.

교류는 친밀도와 꾸미기 목표로 이어진다. 친구 포인트는 소셜 교환 기록으로 관리하며 위인 영입 GP나 기본 재료를 대신하지 않는다. 친밀도 보상과 교환 목록은 받을 내용·조건·기한·중복 보유 처리를 확인하고 선택하게 한다.

선물은 일일·특별·이벤트 유형을 구분하고 보낸 사람·받는 사람·선물 ID·수령 이력을 저장한다. 재료를 지급한다면 종류·품질·수량을 함께 명시하며, 연료는 하나의 재고에 반영하고 골드는 금고 규칙을 적용한다. 방문 보상은 입장료 수입과 구별하고 운영 밸런스에 포함한다.

친구 수·방문·선물 제한과 랭킹 집계·갱신·지급 기준은 서비스 설정에서 한 번 관리하고 화면에 표시한다. 같은 방문이나 수령 요청을 반복해 보상을 늘릴 수 없게 하며, 통신 실패와 재접속 뒤에도 관계·기여·선물·보상 상태가 이어져야 한다. 랭킹은 실제 기록을 집계하고 수치가 바뀐 기준 시점을 남긴다.

| 교류 요소 | 플레이어 행동 | 저장·보상 기준 |
| --- | --- | --- |
| 친구 | 검색·요청·수락·해제·차단 | 관계 상태와 중복 요청의 단일 처리 |
| 파크 방문 | 구경·공룡 상호작용·좋아요·댓글 | 주인 상태 보존, 실제 방문과 보상 이력 분리 |
| 선물 | 일일·특별·이벤트 선물 송수신 | 품목·품질·기한·한도·한 번 수령 |
| 친밀도와 교환 | 교류 누적, 꾸미기와 보상 선택 | 친구 포인트와 GP·기본 재료의 용도 분리 |
| 랭킹 | 운영·수집·교류 기록 비교 | 집계 시점·갱신·지급과 중복 방지 |

### 공룡 경기와 기록 경쟁

스테고케라톱스 첫 전시를 마치면 파크의 **교류 → 공룡 경기**에서 참가 공룡을 등록할 수 있다. 경기마다 코스와 참가 등급을 확인하고, 직접 보유한 개체 중 한 마리를 고른다. 각 플레이어는 자기 파크를 운영하며, 다른 파크와는 등록한 개체의 능력치와 경기 기록을 비교한다. 상대가 접속하지 않은 시간에도 참가하거나 기록에 도전할 수 있다.

| 경기 | 참가와 기록 | 주로 쓰는 능력치 |
| --- | --- | --- |
| 달리기 | 시즌 코스에서 같은 조건의 기록과 순위를 비교한다. 단거리와 지구력 코스에서 유리한 개체가 달라진다. | 속도·체력 |
| 친선 대결 | 같은 참가 등급에서 등록한 상대를 고르면 능력치를 바탕으로 모의 경기를 진행한다. 결과에서 유리했던 구간과 개체의 강점을 확인한다. | 공격성·체력·속도 |

경기 기록은 등록 시점의 능력치를 사용하고 참가 등급별로 집계한다. 참가 전 비교 화면에서 개체의 강점을 확인할 수 있다. 결과와 최고 기록은 해당 공룡의 경기 내역에 남고, 시즌이 끝나면 달성 기록을 기념 배지로 확인한다. 경기 후에도 공룡은 원래 파크로 돌아와 평소대로 전시하고 돌본다. 매력도가 높은 개체는 파크 관람 수요를 끌어올리는 데 유리하다.

## 7. 상점과 수익 모델

서비스는 무료로 파크 운영·탐험·연구·수집을 이어 갈 수 있게 하고 선택 구매와 이용자가 고른 리워드 광고를 연결한다. 광고 시청이나 결제를 첫 시설·첫 탐험·첫 지정 합성의 필수 조건으로 넣지 않는다. 상품 화면은 지급 내용·사용처·중복 보유·구매 재화를 먼저 보여준다.

다이아 팩·기간 구독·시즌 패스·스타터·성장·확장 묶음을 상품군으로 관리한다. 일반 연구원은 시작무료1명과 다이아 추가 영구 구매를 사용하고 이름 있는 위인의 영입은 전용 재화 GP를 사용한다. 위인 조건·비용·효과는 위인 기획을 읽으며 일반 연구원 구매와 혼합하지 않는다.

상품·패스·광고 보상은 DNA 합성 성공률, 첫 지정100%, 보호 횟수, 실제 원종 보유·보존, 재료의 종류·수량·최소 품질 조건을 변경하거나 생략하지 않는다. 추가 병렬 인력도 한 작업 시간을 나누지 않으며 후기 연구 최종하한과 주요 시설 강화 하한은 담당 규칙을 유지한다.

사업 미확정 항목은 이곳에서 관리한다. 현금 가격·재화 패키지 수량·상품별 혜택·구독 기간과 갱신·결제 및 환불 정책·광고 제공 방식과 보상량·시즌 유료 트랙의 판매 조건은 출시 결정 전 확정값으로 표시하지 않는다. 매출 계획은 이용자 규모·잔존율·결제율·LTV/CAC·제작 및 운영비의 가정과 실제 측정을 구분해 계산한다.

| 항목 | 목적 | 설계 기준 |
| --- | --- | --- |
| 다이아 팩 | 선택 재화 공급 | 지급량과 구매 조건을 상품 화면에서 확인 |
| 구독과 패스 | 기간의 목표·꾸미기·편의 연결 | 기간·트랙·수령 이력과 유료 상태 구별 |

## 8. 기술 구조와 품질 기준

클라이언트의 화면과 파크 렌더링을 분리하고 서버를 경제·소유·작업 진행의 정본으로 둔다. React·TypeScript의 UI, PixiJS 파크 표현, 상태·서버 질의 관리, NestJS·Prisma의 API와 저장 계층을 연결한다. 화면의 방문객 연출이나 로컬 시간은 골드·알·공룡·위인 지급을 결정하지 않는다.

입장료·금고·연료·생산·부화·기술 연구·DNA 합성·영입은 비용과 조건을 검증한 뒤 한 번 시작하고 한 번 반영한다. 시작한 작업은 조건·시간·효과 버전과 완료 시각을 고정한다. 중복 요청·동시 접속·재접속에도 재화 이중 차감·중복 수령·인력 이중 반환을 막고 기존 계정·초과 잔액·미수령 완료품을 보존한다.

렌더링은 화면 밖 오브젝트와 불필요한 갱신을 줄이고, 이미지와 오디오는 필요한 순서로 로드한다. 긴 운영 중 화면 이동·탐험·목록·컷신을 반복해 프레임·응답·로딩·메모리를 측정한다. 작은 화면의 한글·표·숫자·초점·선택 상태와 오류 복구도 같은 사용 흐름에서 확인한다.

QA는 인증, 파크와 동선, 자원과 정산, 공룡·부화·합성, 건설·기술·인력, 위인과 GP, 탐험, 스토리, 시즌·소셜·상점, 접근성·성능·저장·보안을 나눠 검증한다. 수치 모델 검산·단위 검사·저장 동시성 검사·전체 플레이·시각 검토는 각각의 증거를 남기고 완료 판정을 합치지 않는다. 구현 범위와 실제 실행 결과는 별도 기술 부록과 작업 기록이 관리한다.

| 검증 축 | 통과 조건 | 확인할 증거 |
| --- | --- | --- |
| 게임 규칙 | 담당 기획의 자원·해금·보유·비용·효과와 일치 | 규칙 대조와 수치 모델 검산 |

## 9. 기획 갱신과 변경 검증

게임 기획은 주제별 담당 원천을 하나씩 둔다. 제작·서비스는 production-and-services.md, 사건과 관계는 스토리와 등장인물, 위인 GP·조건·능력은 위인 기획이 소유한다. 자원·건물·연구·DNA의 수치와 조건은 해당 기획을 읽고 가이드북의 편집 요약에 별도 설정을 만들지 않는다.

변경은 목적과 영향을 확인한 뒤 담당 원천을 먼저 고친다. 재료·확률·하한·수집 분모·인물 관계가 바뀌면 관련 표와 장면·화면·보상·진행 경로를 함께 대조한다. 승인된 내용만 편집 JSON에 반영하고 출처 지문을 갱신한 뒤 목차·본문·색인을 다시 생성한다.

가이드북 생성 후에는 제목·표·한글·쪽수·링크·색인·분할을 실제 출력에서 확인한다. 내용이 바뀐 페이지와 이전 승인 이미지의 지문을 구별하며, 출력의 문장 수정은 담당 원천에 되돌려 반영한다. 수치표 재생성이나 문서 생성만으로 게임 적용을 완료했다고 기록하지 않는다.

플레이 검증과 이관은 별도의 실행 기록으로 남긴다. 검산의 접속 가정과 작업 시간 합을 실제 플레이 기간으로 표시하지 않으며, 장기간 운영·확장과 여러 활동의 병행이라는 목표를 유지한다. 완성한 변경은 담당 문서·편집 요약·출력 검토의 버전을 맞춰 전달한다.

| 변경 단계 | 처리 기준 | 결과 |
| --- | --- | --- |
| 범위 확인 | 목적·영향·담당 원천 확인 | 하나의 변경 범위와 소유 문서 |
| 기획 반영 | 관련 조건·수치·관계·표를 함께 정리 | 담당 원천의 일관된 설계 기준 |
| 편집 갱신 | 승인 내용 요약과 source_sha256 갱신 | 원천과 연결된 JSON |
| 출력 검토 | 목차·본문·표·색인·링크와 페이지 이미지 확인 | 검토 범위와 원본 지문 기록 |
| 적용 검증 | 실제 구현·이관·플레이를 실행해 확인 | 환경과 결과가 있는 작업 기록 |

## 적용 원천과 제작 입력

시각 토큰은 [DESIGN.md](../../DESIGN.md), 기존 SVG의 경로·비율·접지 규약은 [임시 에셋 목록](../../apps/client/public/assets/placeholders/README.md)을 따른다. 제작 시에는 현재 대상 ID와 이 문서의 기준을 적용한다. 화면·오디오·에셋의 구체 납품 목록은 대상별 상태와 파일을 추적하며 기본 수집 분모를 바꾸지 않는다.

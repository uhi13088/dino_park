# 제작·서비스 통합 기획 0.6

기준일: 2026-11-17 · 상태: 현행 제작·서비스 설계 기준안

이 문서는 UI·아트·사운드·에셋 제작, 시즌 운영, 소셜, 상점과 수익 모델, 기술 품질·QA, 기획 갱신 절차를 소유한다. 장기간 파크를 운영·확장하며 운영·탐험·연구·수집을 병행하는 게임을 기준으로 한다. 접속 주기와 접속당 행동 수를 고정하지 않는다.

사건·인물 관계와 시즌 줄거리는 [스토리와 등장인물](story-and-characters.md), 첫 합성까지의 실제 대본은 [초반 스토리](story-progression.md), GP·영입·위인 능력은 [위인 기획](great-figures.md)을 따른다. [자원과 생산](resources-and-production.md)·[밸런스](balance.md)·[건물](buildings.md)·[연구](research-trees.md)·[DNA](dna-and-collection.md)의 수치와 조건은 각 담당 원천이 소유한다. 본문의 설계 기준과 실제 구현·실행 검증의 범위는 별도 기술 부록과 [작업 기록](../../TASK.md)으로 연결한다.

## 1. 화면과 아트 방향

파크 전체에 **큰 형태와 자세를 강조한 3D 조형**을 적용한다. 기본 배율에서는 공룡과 시설의 실루엣이 먼저 읽히고, 확대 화면과 도감에서는 표정·피부·재질이 드러난다. 지도는 2:1 격자에 맞춘 아이소메트릭 시점을 사용한다. 좌상단에서 들어오는 따뜻하고 부드러운 빛과 발밑 그림자로 시설·인물·공룡의 입체감과 접지를 맞춘다.

| 대상 | 공통 비주얼 기준 |
| --- | --- |
| 공룡 | 종을 한눈에 구분하는 형태와 자세를 강조한다. 파라는 두툼한 주황색 볏과 높이 든 목, 영웅 스테고케라톱스는 방패처럼 넓은 붉은 프릴과 묵직한 앞다리, 구릿빛 등판을 살린다. 같은 종은 지도·도감·동작 프레임에서 핵심 형태와 색 배치를 이어간다. |
| 시설 | 사암·목재·구릿빛 금속을 중심으로 입구, 관람, 연구, 생산 시설의 지붕과 몸체를 구별한다. 바닥에 닿는 기준점을 유지하고, 강화 구간마다 높이·지붕·기능이 드러나는 설비에 변화를 준다. |
| 인물 | 파크의 같은 조명을 적용한 친근한 성인 조형을 쓴다. 표정과 복장·장비로 역할을 드러내고, 지도에서 보이는 인물과 리더·위인 초상의 특징을 맞춘다. |
| 지형과 길 | 파크 안팎의 잔디를 잇고 모래·얕은 물·바위가 섞이는 해안과 숲을 표현한다. 정문·관람길·외곽 경계·서식지 울타리는 모양과 재질로 읽히게 하고 공룡의 볏과 프릴이 시설에 가려지는지 기본 배율에서 확인한다. |
| 파크 HUD | 중앙을 지도로 열어 둔다. 왼쪽 위는 알렉스 초상에 파크 레벨·경험치와 개장 상태를 겹쳐 표시한다. 오른쪽 위는 건설자와 골드·목재·석재·금속을 입체 아이콘과 현재 수량으로 보여준다. 아래 양쪽 모서리의 반투명 묶음에서 도감·위인과 운영·건설을 열고, 건설은 금색으로 강조한다. 탐험과 더 보기는 묶음 옆의 작은 버튼에서 연다. 공사 중인 시설 위에는 남은 시간을 표시한다. |

2.5D 파크 에셋은 [승인된 스테고사우루스 조형 시안](../assets/reference/stegosaurus-character-direction.webp)의 큼직한 형태와 또렷한 표정을 기준으로 제작한다. 공룡의 둥근 몸체와 종별 특징을 살리고, 앞으로 만드는 시설에도 형태가 한눈에 읽히는 조형과 좌상단의 따뜻한 빛을 적용한다. 시설·경계·HUD와 공룡이 함께 보이는 크기는 [640px 가로 파크 배치 시안](../assets/reference/landscape-direction.webp)을 따른다.

파라·이구아노돈·트리케라톱스·스테고케라톱스는 새 조형으로 파크와 도감에 표시된다. 파라는 대기 자세와 여섯 자세의 걷기 동작에 같은 볏과 몸통 무늬를 사용한다. 기본 배율에서 볏·뿔·프릴·등판을 구별하고, 확대하면 표정과 몸통의 입체감이 보인다.

시설 배치는 미리보기·비용 확인·확정·취소를 지원한다. 현재 목표와 탐험 진입은 조작 흐름에서 확인한다. 장기 건설·연구 중에도 운영·탐험·수집 화면을 오갈 수 있게 한다.

도감은 검색·등급·획득 분류와 수집·현재 보유·계보를 함께 보여준다. 밝은 읽기 면을 사용하며 등급과 보유 상태를 글자로도 전달한다. 구현된 도감 화면의 세부 토큰은 [디자인 시스템](../../DESIGN.md)을 따른다. 공룡 초상은 같은 종의 지도 스프라이트와 특징을 맞춘다.

모바일과 넓은 화면에서 핵심 조작과 읽기 순서를 유지한다. 선택한 항목의 제목과 복귀 위치를 보존하고 키보드 초점·로딩·빈 결과·오류·재시도를 표시한다. 공사·부화·기술 연구·DNA 합성의 진행과 수령 상태를 구별하며, 비용·효과·시간은 각 담당 기획의 값을 읽는다.

| 화면 묶음 | 주요 행동 | 반드시 보여줄 정보 |
| --- | --- | --- |
| 메인 파크 | 관찰·배치·돌봄·개장과 시설 이동 | 외곽 경계·길·관람 가능 상태, 입장료와 금고 한도 |
| 도감과 상세 | 검색·분류·개체와 계보 확인 | 수집과 현재 보유, 획득 경로, 실제 원종 보유 조건 |
| 탐험 | 장소·목표 선택, 조사와 결과 수령 | 준비비·조사 시간·보상. 특수 원정의 필요 연료. |
| 건설과 연구 | 비용 확인, 작업 시작과 완료 확인 | 유휴 인력·선행 조건·완료 시각·적용 효과 |
| 스토리와 인물 | 대화·선택지·인물 기록 열람 | 현재 장면·선택 기록·다음 플레이 목표 |
| 상점과 위인 | 상품 또는 위인 선택과 최종 확인 | 구매 재화·영입 GP·조건·중복 보유와 지급 결과 |

### 파크 경계와 정문 길

오른쪽 확대·축소 버튼 아래의 **섬 전체 보기**를 누르고 지도를 끌어 해안·평원·숲·암릉을 둘러본다. 같은 자리에서 집 모양의 **내 파크로 돌아가기**를 누르면 울타리 안 파크가 다시 화면에 맞춰진다. 건설할 수 있는 범위는 파크 울타리와 건설 중 나타나는 격자로 확인한다. 정문 바깥의 진입로와 안쪽 관람길은 전시까지 이어진다.

왼쪽 위 알렉스 초상에서 파크 레벨·경험치·개장 상태를 확인하고, 오른쪽 위에서 건설자와 모은 재화를 확인한다. 왼쪽 아래의 도감·위인 옆 나침반으로 탐험을, 오른쪽 아래의 운영·건설 옆 점 세 개로 더 보기를 연다.

첫 조사에 쓰는 **파크 뒤 초원**은 파크 지도에서 바로 열 수 있다. 운영 안내를 닫고 초원 표시를 누르거나, 첫 관람대를 완공한 뒤 운영 안내에서 **첫 탐험가 파견**을 누른다. [파크 뒤 초원 첫 조사](exploration-spots.md#파크-뒤-초원-첫-조사)

### 파크 섬 지형과 확장 동선

시작 파크에서 해안과 숲 쪽을 바라볼 수 있게 하고, 섬 지도에 보유 부지와 매입할 수 있는 인접 필지를 표시한다. 중앙 평원은 큰 전시가 들어갈 공간을 남기고, 뒤쪽 암릉과 해안 끝 폭포는 지도에서 방향을 잡는 기준으로 쓴다. 시안의 비율과 위치는 건설 격자에 맞춘다. [섬 전체 디자인 시안](../assets/reference/island-map-direction.png)

| 구역 | 지도에서 읽히는 형태 | 파크를 설계하는 선택 |
| --- | --- | --- |
| 초승달 만과 시작 파크 | 얕은 청록빛 물, 길게 이어지는 밝은 모래, 만을 감싸는 바위 아치 옆의 작은 정문 | 입구 옆을 비워 두고 해안 방향에 두 번째 전시와 관람대를 둔다. 해양 생물 사육이 열리면 해안을 따라 긴 형태의 해양관을 계획할 수 있다. |
| 고사리 숲 | 울창한 숲이 밝은 공터를 둘러싸고, 입구에서 공터까지 숲 가장자리를 따라 길이 이어진다. | 공터를 하나의 대형 서식지로 쓰거나 작은 전시 두 곳으로 나눈다. 기존 전시와 관람길을 잇고 두 번째 관람 지점을 어디에 둘지 비교한다. |
| 중앙 초원 | 숲과 암릉 사이에 넓고 평탄한 풀밭이 길게 열린다. | 여러 초원 블록을 이어 넓은 합사 전시를 마련한다. 익룡 돔까지 계획한다면 최대 14×14 돔과 접근 동선을 함께 놓을 수 있는 연속 공간을 남긴다. |
| 층층 암릉 | 옅은 사암 단층이 한 방향으로 이어지고 아래쪽에는 넓고 낮은 평탄면이 있다. | 절벽은 먼 거리에서도 방향을 알려준다. 아래쪽 평탄면을 확보하면 바위 지형을 등진 관람 지점과 대형 시설을 배치할 수 있다. |
| 폭포 물목 | 섬 가장자리를 따라 내려오는 물이 두 단의 폭포와 조용한 연안 웅덩이로 이어진다. | 물과 절벽을 조망하는 해안 산책 지점의 장기 후보지다. 실제 사용 단계에는 웅덩이 옆 평탄면과 진입 경로를 함께 확보한다. |

같은 예산이라도 해안 쪽 필지는 해양관과 긴 해안 산책로를 배치하기 좋고, 숲 쪽 필지는 공터를 연결해 넓은 서식지를 만들기 좋다. 두 방향 모두 생산시설, 관람시설 또는 나중에 쓸 빈 공간으로 활용할 수 있다. 지도에서 지형과 실제 건설 범위, 경계를 넓혔을 때 이어지는 길을 판단할 수 있도록 한다.

시작 부지와 기존 보유 부지는 평평한 건설면으로 보존한다. 숲의 건설 후보지에서는 옮길 수 있는 나무를 쓰고, 암릉 아래의 평탄지는 시설과 진입로가 함께 들어가는지 확인한다. 섬 육지의 약 절반을 파크로 넓혔을 때에도 숲·해안·암릉이 구별된다. 2.5D 경영 화면에서 셔틀버스의 정문과 전시 사이 노선을 읽을 수 있게 한다. 사파리에서는 두 정차 지점을 연결하는 지프 코스를 확인한다. [건물과 부지 확장](buildings.md#81-토지의-유료-확장과-입구-미리보기)

| 지도 배율 | 먼저 알아볼 정보 | 화면 표현 |
| --- | --- | --- |
| 섬 전체 | 내 파크, 초승달 만, 숲 공터, 암릉과 골짜기 사이의 방향 관계 | 서로 다른 해안 윤곽과 높낮이, 한 덩어리로 읽히는 수관, 연안의 수심 차와 암벽 그림자. 개별 나무·시설 이름은 축소한다. |
| 확장 미리보기 | 어느 필지를 살 수 있고 정문에서 길이 이어지는가 | 기존 부지와 새 경계, 입구 연결을 함께 표시한다. |
| 관람 노선 | 어느 구역까지 닿고 어디서 대기열이 길어지는가 | 노선 편집 중에 정류장과 주행 경로를 표시한다. |
| 기본과 확대 | 길 입구, 건물과 울타리의 접지점, 움직이는 공룡 | 갯바위·모래·잔물결·갈대, 숲 하층과 그늘을 드러낸다. 캐노피와 절벽 그림자가 길 또는 시설 선택을 가리지 않게 한다. |

### 섬 지형 제작과 검토

| 제작 방법 | 적합한 범위 | 확인할 제작 부담 |
| --- | --- | --- |
| GPT 이미지로 지형 제작 | 아트 방향 비교, 시야가 고정된 전경 그림, 재질·배경 오브젝트 초안 | 구역 간 접합, 배치 위치와 그림자의 일관성, 확대용 디테일, 구역을 바꿀 때 다시 만들 범위를 사람이 관리한다. |
| Blender 지형을 2.5D로 렌더 | 해안의 높이, 암벽과 공터, 곡선이 이어지는 구역을 한 원본에서 제작하고 여러 배율로 출력 | 3D 원본 제작과 내보내기 작업이 생긴다. 현재 시설 스프라이트와 시점·접지점 검증이 필요하다. |
| 실시간 3D | 카메라 회전과 경사면 위 실제 이동이 주요 조작일 때 | 기존 시설·공룡·지도 렌더와 입력을 3D에 맞춰야 한다. 휴대폰 성능 검증 범위도 커진다. |

이 시안에서는 GPT로 아트 방향과 텍스처 후보를 잡고, Blender로 바닥과 큰 지형을 만들며, 게임에서는 기존 2.5D 카메라를 사용하는 조합을 우선 검토한다. Blender에서 건설 기준면을 먼저 잡고 해안, 얕은 물의 바닥, 숲 공터, 절벽과 폭포 골짜기에 높이를 준다. 수평에서 30도 내려다보는 45도 회전 직교 카메라로 2:1 지도 투영을 맞추고, 현재 정문과 서식지를 같은 배율에서 겹쳐 접지와 축척을 확인한다. [Blender 카메라](https://docs.blender.org/manual/en/latest/render/cameras.html)

게임에 넣을 때는 구역 단위 지면 이미지, 해안·절벽 전경, 반복 가능한 수면과 숲 오브젝트를 따로 출력한다. 건설·이동·통행을 판정하는 좌표 데이터는 기존 격자로 관리한다. 바닥과 전경을 분리해 공룡과 방문객을 그 사이에서 깊이 순서에 맞춰 표시한다. 섬 전경과 세부 렌더를 같은 지형 원본에서 내보내고, 기존 PixiJS 카메라로 맞물리는지 확인한다. [PixiJS 에셋](https://pixijs.com/8.x/guides/components/assets)

첫 제작 표본은 정문, 만의 모래와 얕은 물, 숲 공터 입구까지 담는다. 640×296 가로 화면에서 이름을 읽기 전에 세 장소를 구분하고, 기본 배율에서 관람길과 맞닿는 전시 경계를 찾고, 확대하면 물가·숲 가장자리의 입체감을 확인한다. 두 전시 배치 예시로 건설 가능 칸, 길 연결, 공룡 가림을 비교한다. 플레이어에게 같은 확장 조건을 주고 먼저 고른 자리와 이유, 다음에 열어 보고 싶은 곳을 묻는다. 각 선택의 이점과 포기한 배치를 설명할 수 있는지 관찰한다.

## 2. 음악과 사운드 제작

사운드는 섬의 몰입감, 공룡과 인물에 대한 정서적 연결, 행동에 대한 명확한 피드백과 편안한 장시간 청취를 목표로 한다. 평상시 파크·초식 구역·밤과 해변은 평화롭게, 안전 위기와 이야기의 절정은 긴장감 있게 구분한다.

음악은 오케스트라를 중심으로 전자음과 월드 악기 색채를 섞는다. 현악은 감정선, 목관은 자연의 신비, 금관과 타악은 장엄함과 위기, 패드와 가벼운 플럭은 몽환적이거나 귀여운 순간을 맡는다. 같은 주제 선율을 발견·재건·이별·계승 장면에서 변주한다.

장소·시간대·활동에 맞춰 음악 층과 환경음을 전환하고 급격한 단절을 피한다. 중요한 대사에는 음악과 환경음을 낮추는 덕킹을 적용한다. 인물 보이스와 컷신은 스토리와 등장인물 정본의 성격·관계·시점을 따르며 기록 음성과 현재 대사를 구별한다.

음악·효과음·보이스의 음량과 음소거를 각각 조절한다. 반복 울음과 획득음은 겹침과 빈도를 제한하고, 무음 상태에서도 성공·오류·위기를 글자와 화면으로 전달한다. 오디오는 루프 경계·전환·동시 재생·압축 손실을 실제 재생 환경에서 검수하고 대상 ID별 제작 목록으로 관리한다.

| 분류 | 제작 방향 | 검수 기준 |
| --- | --- | --- |
| 메인과 장소 BGM | 파크의 일상·시간대·지역 분위기 | 긴 청취의 피로, 반복 경계와 장면 전환 |
| 스토리 BGM | 발견·감동·위기·이별과 계승 | 대사 전달과 장면의 감정 흐름 |
| 공룡 효과음 | 종·크기별 울음, 대기·기쁨·배고픔·이동·섭식 | 서로 다른 실루엣에 맞는 음색, 과도한 중첩 방지 |
| 환경음 | 바람·물·숲·해변과 구역의 생활감 | 거리와 실내·실외·수중의 구분 |
| UI와 게임 피드백 | 선택·확인·획득·건설·돌봄의 반응 | 동작 결과 구분과 시각 피드백 병행 |
| 보이스와 믹싱 | 인물별 어조, 기록 음성, 덕킹 | 정본 관계·시점과 음량 균형 |

## 3. 에셋 제작과 파일 기준

제작 명세는 공통 스타일에 대상의 특징·상태·포즈·크기를 조합한다. 공룡은 대기·이동·섭식·수면·초상, 인물은 초상·전신·감정, 시설은 역할과 강화 구간의 외형으로 나눈다. 파일과 스프라이트에는 대상 ID·상태·크기·프레임 정보를 연결하고 투명 배경과 바닥 기준점을 유지한다.

배포용 파크 오브젝트는 2:1 타일 격자와 공통 조명을 적용한 2.5D 래스터 스프라이트다. 현행 지도는 64×32 타일을 사용한다. 투명 PNG를 원본으로 관리하고 배포 용량을 줄일 때는 알파 채널을 보존하는 WebP를 사용한다. 같은 공룡의 동작 프레임은 발의 위치와 그림자 방향을 맞추고, 시설 강화 외형은 바닥 기준점과 점유 영역에 맞춘다. 초기 SVG와 기존 에셋은 엔진의 배치·접지와 교체 위치를 확인할 때 참고한다.

### 사파리 공룡 동작의 제작 분량

15초 물가 대치 시범 장면의 티렉스와 스테고사우루스는 각각 16개와 19개 뼈대로 구성한 독립된 Blender 5.2.3 리그를 쓴다. 종마다 대기 8장·걷기 12장·위협 10장·공격 12장·피격 및 중재 반응 8장·후퇴 10장으로 여섯 동작과 서로 다른 프레임 60장을 사용한다. 스테고사우루스는 꼬리를 들기 전에 몸을 돌리는 동작 네 장을 더해 일곱 동작·64프레임을 사용한다. 공룡 한 마리의 192×160 픽셀 프레임은 1,536×1,280 픽셀의 8×8 아틀라스에 넣는다. 티렉스의 마지막 네 칸은 투명하고 스테고사우루스는 64칸을 모두 쓴다.

| 공룡 | Blender 리그 원본 | 배포 WebP | RGBA로 펼친 아틀라스 |
| --- | ---: | ---: | ---: |
| 티렉스 | 641,000바이트 | 244,300바이트 (238.57 KiB) | 7.5 MiB |
| 스테고사우루스 | 600,284바이트 | 354,554바이트 (346.24 KiB) | 7.5 MiB |

한 방향을 렌더한 뒤 같은 아틀라스를 좌우 반전해 맞은편 방향을 표현한다. 별도로 그린 두 시점에 각각의 반전을 더해 네 방향을 만들 경우, 같은 동작 수와 해상도에서 티렉스는 120프레임, 스테고사우루스는 128프레임을 제작한다. 종당 두 아틀라스의 압축 해제 용량은 약 15 MiB다. 실제 WebP 파일 크기는 공룡마다 달라진다.

물가 배경과 지프·로봇 소품은 ImageGen으로 만들었다. 시범 관람의 물가는 한 장으로 합성된 시험 배경이다. 사파리 관리에서는 물가와 수풀을 옮길 수 있다. 높은 보강 울타리와 양옆 기둥이 선 차량 출입문으로 육식 우리를 구분한다. 공룡 발과 지프 바퀴의 아래쪽에 그림자를 그려 지면에 닿아 보이게 한다. 스테고사우루스와 티라노사우루스는 승인한 2.5D 공룡 조형을 따른다. 시범 장면의 위협·타격·중재음 세 개는 직접 합성한 MP3를 사용한다. 공룡 둘과 공용 배경·지프·로봇·효과음을 합친 장면의 배포 파일은 총 952,292바이트(약 929.97 KiB)다. 편집용 Blender 원본은 제작 자료에 보관한다. [원본과 배포 파일](../../apps/client/src/assets/README.md#사파리-물가-대치)

### 스테고사우루스 실시간 3D 시험

한 마리의 Blender 리그에 대기(`Idle` 2초)·몸 돌리기(`Turn` 1.1초)·꼬리 반격(`TailStrike` 1.2초)을 넣어 GLB 한 파일로 내보낸다. 직교 카메라에서 리그를 실시간으로 재생하며 기본 배율과 확대를 전환한다. 확대 배율은 가로 화면 높이에 맞춰 공룡의 동작이 조작 버튼에 가려지지 않게 조절한다. 시험 범위는 스테고사우루스 한 종의 표시와 동작이다.

[승인 조형 시안](../assets/reference/character-direction.webp)의 묵직한 몸통과 굵은 발을 바탕으로 시범 관람의 스테고사우루스에 캐릭터 표정을 더했다. 호박색 눈과 눈썹을 키우고 주둥이를 짧고 넓게 빚었다. 넓은 올리브색 무늬, 꿀빛 배와 금빛 가장자리를 두른 주황색 골판으로 기본 배율에서도 윤곽과 색이 읽히도록 했다. [물가 이미지](../../apps/client/public/assets/safari-encounter/field.webp)에 맞춰 왼쪽 위 햇빛과 반사광을 비추고, 몸 자세에 따라 달라지는 부드러운 그림자를 발밑에 붙인다.

[배포 모델](../../apps/client/public/assets/safari-encounter/stegosaurus-realtime.glb)은 5,665,496바이트(5.40 MiB)다. 36,568개 삼각형, 관절 19개, 1,536×1,536 픽셀의 색·표면 요철 텍스처 두 장을 포함한다. [편집 원본과 제작 스크립트](../../apps/client/src/assets/README.md#스테고사우루스-3d-관람)

### 실험 하이브리드 외형

처음 연구하는 계통은 두 원종과 성향의 특징을 바탕으로 AI로 공룡 전신을 만든다. 관람형에서 큰 프릴이 발달하면 목과 어깨도 그 무게를 받치는 형태로 함께 설계한다. 질주형은 낮은 자세와 균형을 잡는 꼬리로 표현한다. 부모·성향·등급이 같은 조합은 한 계통의 외형을 공유한다. 도감에서 본 새 개체를 파크에 배치하면 같은 모습으로 전시된다.

실험 외형의 적용 기준은 공통 카메라의 투명한 대기 이미지다. 걸음과 급식 동작을 제작할 때는 같은 전신의 관절과 바닥 기준점을 이용한다. 기본 배율에서 각 계통의 윤곽을 확인하고 확대 화면에서 부모의 특징과 몸의 연결을 살핀다.

### 플레이 흐름별 제작 순서

1. 플레이할 흐름을 따라가며 새 그림이 필요한 화면과 상태를 적는다. 이미 같은 용도로 쓸 수 있는 이미지를 확인하고 필요한 것만 제작 목록에 올린다.
2. [화면과 아트 방향](#1-화면과-아트-방향)의 승인 시안을 먼저 고른다. [구버전 프롬프트 자료](../assets/dino_park_asset_main.md)는 종의 특징과 시설·인물의 역할을 찾는 데 쓴다. 기존 초상과 관람대 외형은 구현·비교용 예시로 관리하고, 새 제작의 조형·재질·조명과 카메라는 승인 시안을 따른다.
3. 제작 요청에는 대상 ID, 사용 화면과 상태, 기준 이미지, 화면 표시 크기와 원본 해상도, 배치 방향·바닥 기준점·점유 칸, 투명 PNG 원본과 배포용 WebP의 파일명을 적는다.
4. 실제 게임에 시험 배치한다. 640px 가로 기본 배율에서 읽히는 형태·가림과 확대 화면에서 드러나는 표정·재질을 각각 확인한다. 이동 프레임의 접지, 울타리 앞뒤 순서, 시설 선택·수확·강화 시 가독성과 모바일 조작도 점검한다.
5. 검수를 마친 파일을 정해진 경로와 에셋 매핑에 등록하고 대상 ID에 연결한다. 공통 표현이 안정된 뒤 같은 계열의 레벨과 포즈를 묶어 제작한다.

| 제작 범위 | 한 번에 맞추는 화면과 에셋 |
| --- | --- |
| 첫 파크 장면 | 가로 배치 시안의 파라와 스테고케라톱스, 입구·초원 서식지·하이브리드 서식지·관람대·DNA 연구소·벌목장·채석장 7개 시설을 맞춘다. 잔디·길·물가·울타리, 방문객과 리더 초상, 운영 HUD를 같은 장면에서 비교한다. |
| 첫 전시까지의 플레이 | [첫 개장과 첫 전시](production-direction.md#첫-개장과-첫-전시)에 따라 개장·급식·수확·탐험·부화·합성에 필요한 그림을 보강한다. 공룡의 대기·걷기·섭식과 장소별 결과 화면을 지도·도감·상세에서 연결해 검수한다. |
| 확장과 수집 | 이후 열리는 시설의 강화 외형, 추가 종, 인물·위인, 지역과 화면을 해금 흐름별로 묶는다. 한 묶음씩 실제 배치와 모바일에서 확인한 뒤 다음 묶음으로 확장한다. |

### 시설별 기본 외형

서식지 9종, 연구 6종, 관람 6종, 편의 12종, 생산 9종, 운영 7종의 기본 외형은 투명 WebP를 사용한다. 시설마다 같은 2:1 지도 투영과 바닥 눈금을 적용한다. 동일한 시설 그림을 지도와 시설 선택 화면에 사용하고, 배치 미리보기에서 기존 바닥 기준에 맞춰 표시한다. [시설별 이미지와 경로](../../apps/client/src/assets/README.md)에서 파일을 찾을 수 있다.

관람대와 실외 서식지 7종은 Lv.5 완공 시 외형을 교체한다. 실외 서식지는 [울타리 강화 규칙](buildings.md#실외-서식지-울타리-강화)을 따른다. 관람대는 `viewing-platform.webp`에서 `viewing-platform-lv5.webp`로 바뀐다.

육식 서식지와 보안센터의 기본 외형은 사암을 공통 재질로 쓴다. [육식 서식지 Lv.1](../../apps/client/public/assets/buildings/habitat-carnivore-electric.webp)부터 전기 울타리와 짙은 목재를 쓰고 관람객 쪽 울타리를 낮춘다. [Lv.5](../../apps/client/public/assets/buildings/habitat-carnivore-lv5.webp)에서는 절연 기둥과 출입부 잠금 장치를 보강한다. [보안센터](../../apps/client/public/assets/buildings/operation-security-center.webp)는 따뜻한 사암 벽과 테라코타 지붕, 경비 출입구로 구분한다.

다음 제작 범위에는 실외 서식지 7종의 Lv.10·15·20·25 외형 28종과 관람대의 Lv.10 이후 외형이 있다. 익룡 돔은 공간 단계의 외형 시안이 있고 실제 단계 전환 아트가 남아 있다. 해양관과 다른 시설의 강화 외형, 환경 장식 6종(공룡 동상, 분수대, 화단, 가로등, 울타리, 길)도 해당 제작 흐름에서 다룬다.

현행 건물 카탈로그 55종의 배치 크기는 1×1, 2×2, 3×3, 4×4 중 하나다. 육식 서식지는 3×3, 보안센터는 2×2를 사용한다. 크기는 배치 판정에 적용하며 파크 화면에는 칸 수를 표시하지 않는다. 두 시설 모두 기존 회전 조작으로 같은 자리에서 외형을 좌우 반전한다.

[서식지 블록과 익룡 돔 공간](buildings.md#서식지-블록과-익룡-돔-공간)의 외형도 같은 2:1 지도를 기준으로 설계한다. 초원·해양관의 내부 표면과 가장자리, 모서리 조각은 서로 이어지는 바닥 기준을 공유한다. 익룡 돔은 각 공간 단계에 맞는 실루엣과 바닥 범위를 사용한다.

기본 제작 대상은 공룡 83종, 건물 55종, 위인 50명이다. 같은 인물·종의 변형과 시즌 연출은 ID에 연결하고 별도 수집 항목을 만들 때만 분모를 변경한다. 종별 실루엣·성별 또는 연령 표현·의상·음색·상태별 납품물은 제작 목록에서 관리하며 목록의 목표 수와 납품 파일 수를 구별한다.

시설은 Lv.5·10·15·20·25의 큰 변화를 같은 건물로 인식할 수 있게 표현한다. 스킨은 외형 변형이며 게임 효과는 별도 담당 규칙을 따른다. 시각적 크기나 프롬프트 문구로 수용량·물리 점유·수익·합성 능력을 정하지 않는다. 컷신·초상·보이스의 인물 나이와 관계는 스토리와 등장인물 정본을 따른다.

## 4. 시즌 운영과 이벤트

시즌은 본편 이후에도 같은 파크를 운영하며 이야기·탐험·수집 목표를 확장하는 방식이다. 네 시즌의 이름·등장인물·다섯 장씩 총20장의 줄거리는 스토리와 등장인물 정본이 소유한다. 이 절은 공개·목표 진행·보상·종료 처리를 담당한다.

시즌의 시작과 종료, 대상 플레이어, 목표, 보상, 수령 기한을 한 안내에서 확인하게 한다. 오프닝은 새 이야기를 소개하고, 공동 탐험·퀴즈·기록 수집·복원 공사·피날레는 평소의 파크 운영과 연결한다. 공동 목표는 실제 기여를 기록하며 재접속이나 같은 요청으로 기여와 보상을 중복 처리하지 않는다.

시즌 패스는 스토리·일일·주간·시즌 목표의 진행을 한 화면에서 연결하고 무료·선택 유료 트랙의 보상을 구분한다. 결제 없이도 본편의 필수 성장과 첫 지정 합성에 도달할 수 있게 한다. 패스 진행은 미션과 보상 이력에 따라 기록하며 달력의 경과만으로 미완료 플레이를 완료하지 않는다.

일지·기억·에덴의 핵 등 이야기 소품은 장면 진행 기록으로 관리한다. 시즌 진행 포인트와 이벤트 교환 물품은 기본 소모 재료9종·위인 영입 GP와 분리한다. 보상에 알이나 재료를 사용할 때는 기존 획득 조건·품질·보유·한도를 명시하고, 시즌 종료가 파크·수집·진행 중 작업을 초기화하지 않게 한다.

| 운영 단계 | 플레이와 안내 | 진행·보상 처리 |
| --- | --- | --- |
| 시작 안내 | 시즌 목표·대상·시작과 종료·수령 기한 제시 | 플레이 조건과 보상을 공개 전에 함께 고정 |

| 공동 탐험과 복원 | 개별 기여를 공동 목표에 누적 | 기여·지급의 중복 방지와 개인 진행 보존 |
| 시즌 패스 | 무료·선택 유료 트랙의 목표와 보상 확인 | 구매 상태·완료 목표·수령 이력을 구별 |
| 피날레와 종료 | 최종 목표와 남은 보상 안내 | 기한 처리 후에도 파크와 영구 수집 기록 보존 |

## 5. 시즌 생물과 인물 제작 목표

기본 수집 목표는 공룡83종과 위인50명으로 유지한다. 아래 생물20개 이름과 인물12명의 시즌 제작 대상은 확장용 목록이며, 같은 인물이나 종을 본편 분모에 중복 합산하지 않는다. 메갈로돈 자연종과 메갈로돈 알파처럼 별도 개체·외형을 구별하고, 정본이 같은 대상으로 정한 항목은 하나의 ID에 연결한다.

생물은 시즌 환경에 맞는 외형·서식 조건·알 또는 획득 목표·돌봄·전시를 함께 제작한다. 일반 수집에 추가하려면 등급·획득 경로·서식지·재료나 레시피의 담당 명세를 먼저 갖춘다. 이름이나 컷신 등장만으로 소유 공룡을 지급하거나 합성 레시피를 만들지 않는다.

인물은 스토리와 등장인물 정본의 관계·연령·시간 순서를 따른다. 엘리자베스 우는60대 연구자이며 진의 스승이다. 아서 해먼드는 시즌1 마지막 여정 이후 유산 기록으로 제작하며 살아 있는 영입 직원으로 되돌리지 않는다. 기본50명의 동일 ID 기록 수집과 GP 조건·효과는 위인 기획이 소유한다.

시즌의 특수 외형과 연출을 기본 수익·합성 성공률·첫100%·재료 조건·후기 연구 최종하한을 바꾸는 효과로 해석하지 않는다. 위인 배정 가능 여부와 능력은 위인 기획을, 공룡의 자연종·변종·하이브리드 분류와 합성은 DNA 기획을 따른다.

## 6. 친구 방문과 교류

친구를 검색해 요청·수락한 뒤 파크를 방문하고, 공룡과 교감하거나 좋아요·댓글을 남기며 선물을 주고받는다. 관계 관리에는 요청 취소·거절·친구 해제와 차단을 포함하고, 방문 화면은 주인의 파크를 관찰하는 상태와 내 파크 편집을 구별한다.

교류는 친밀도와 꾸미기 목표로 이어진다. 친구 포인트는 소셜 교환 기록으로 관리하며 위인 영입 GP나 기본 재료를 대신하지 않는다. 친밀도 보상과 교환 목록은 받을 내용·조건·기한·중복 보유 처리를 확인하고 선택하게 한다.

선물은 일일·특별·이벤트 유형을 구분하고 보낸 사람·받는 사람·선물 ID·수령 이력을 저장한다. 재료를 지급한다면 종류·품질·수량을 함께 명시하며, 골드는 금고 규칙을 적용한다. 방문 보상은 입장료 수입과 구별하고 운영 밸런스에 포함한다.

친구 수·방문·선물 제한과 랭킹 집계·갱신·지급 기준은 서비스 설정에서 한 번 관리하고 화면에 표시한다. 같은 방문이나 수령 요청을 반복해 보상을 늘릴 수 없게 하며, 통신 실패와 재접속 뒤에도 관계·기여·선물·보상 상태가 이어져야 한다. 랭킹은 실제 기록을 집계하고 수치가 바뀐 기준 시점을 남긴다.

| 교류 요소 | 플레이어 행동 | 저장·보상 기준 |
| --- | --- | --- |
| 친구 | 검색·요청·수락·해제·차단 | 관계 상태와 중복 요청의 단일 처리 |
| 파크 방문 | 구경·공룡 상호작용·좋아요·댓글 | 주인 상태 보존, 실제 방문과 보상 이력 분리 |
| 선물 | 일일·특별·이벤트 선물 송수신 | 품목·품질·기한·한도·한 번 수령 |
| 친밀도와 교환 | 교류 누적, 꾸미기와 보상 선택 | 친구 포인트와 GP·기본 재료의 용도 분리 |
| 랭킹 | 운영·수집·교류 기록 비교 | 집계 시점·갱신·지급과 중복 방지 |

### 공룡 경기와 기록 경쟁

스테고케라톱스 첫 전시를 마치면 파크의 **교류 → 공룡 경기**에서 참가 공룡을 등록할 수 있다. 경기마다 코스와 참가 등급을 확인하고, 직접 보유한 개체 중 한 마리를 고른다. 각 플레이어는 자기 파크를 운영하며, 다른 파크와는 등록한 개체의 능력치와 경기 기록을 비교한다. 상대가 접속하지 않은 시간에도 참가하거나 기록에 도전할 수 있다.

| 경기 | 참가와 기록 | 주로 쓰는 능력치 |
| --- | --- | --- |
| 달리기 | 시즌 코스에서 같은 조건의 기록과 순위를 비교한다. 단거리와 지구력 코스에서 유리한 개체가 달라진다. | 속도·체력 |
| 친선 대결 | 같은 참가 등급에서 등록한 상대를 고르면 능력치를 바탕으로 모의 경기를 진행한다. 결과에서 유리했던 구간과 개체의 강점을 확인한다. | 공격성·체력·속도 |

경기 기록은 등록 시점의 능력치를 사용하고 참가 등급별로 집계한다. 참가 전 비교 화면에서 개체의 강점을 확인할 수 있다. 결과와 최고 기록은 해당 공룡의 경기 내역에 남고, 시즌이 끝나면 달성 기록을 기념 배지로 확인한다. 경기 후에도 공룡은 원래 파크로 돌아와 평소대로 전시하고 돌본다. 매력도가 높은 개체는 파크 관람 수요를 끌어올리는 데 유리하다.

## 7. 상점과 수익 모델

서비스는 무료로 파크 운영·탐험·연구·수집을 이어 갈 수 있게 하고 선택 구매와 이용자가 고른 리워드 광고를 연결한다. 광고 시청이나 결제를 첫 시설·첫 탐험·첫 지정 합성의 필수 조건으로 넣지 않는다. 상품 화면은 지급 내용·사용처·중복 보유·구매 재화를 먼저 보여준다.

다이아 팩·기간 구독·시즌 패스·스타터·성장·확장 묶음을 상품군으로 관리한다. 일반 연구원은 시작무료1명과 다이아 추가 영구 구매를 사용하고 이름 있는 위인의 영입은 전용 재화 GP를 사용한다. 위인 조건·비용·효과는 위인 기획을 읽으며 일반 연구원 구매와 혼합하지 않는다.

상품·패스·광고 보상은 DNA 합성 성공률, 첫 지정100%, 보호 횟수, 실제 원종 보유·보존, 재료의 종류·수량·최소 품질 조건을 변경하거나 생략하지 않는다. 추가 병렬 인력도 한 작업 시간을 나누지 않으며 후기 연구 최종하한과 주요 시설 강화 하한은 담당 규칙을 유지한다.

사업 미확정 항목은 이곳에서 관리한다. 현금 가격·재화 패키지 수량·상품별 혜택·구독 기간과 갱신·결제 및 환불 정책·광고 제공 방식과 보상량·시즌 유료 트랙의 판매 조건은 출시 결정 전 확정값으로 표시하지 않는다. 매출 계획은 이용자 규모·잔존율·결제율·LTV/CAC·제작 및 운영비의 가정과 실제 측정을 구분해 계산한다.

| 항목 | 목적 | 설계 기준 |
| --- | --- | --- |
| 다이아 팩 | 선택 재화 공급 | 지급량과 구매 조건을 상품 화면에서 확인 |
| 구독과 패스 | 기간의 목표·꾸미기·편의 연결 | 기간·트랙·수령 이력과 유료 상태 구별 |
| 스타터·성장·확장 묶음 | 성장 구간에 맞는 선택 상품 제시 | 기본 무료 진행과 보호 규칙 유지 |
| 리워드 광고 | 플레이어가 선택한 추가 편의 | 시청 의사·지급 결과·중복 처리 확인 |
| 위인 영입 | 이름 있는 인물과 유산 기록 수집 | GP 사용, 위인 정본의 조건·효과·기록형 구별 |
| 사업 지표 | 가정별 지속 운영 규모와 비용 검토 | 예측 입력과 실제 성과를 구별 |

## 8. 기술 구조와 품질 기준

클라이언트의 화면과 파크 렌더링을 분리하고 서버를 경제·소유·작업 진행의 정본으로 둔다. React·TypeScript의 UI, PixiJS 파크 표현, 상태·서버 질의 관리, NestJS·Prisma의 API와 저장 계층을 연결한다. 화면의 방문객 연출이나 로컬 시간은 골드·알·공룡·위인 지급을 결정하지 않는다.

입장료·금고·생산·부화·기술 연구·DNA 합성·영입은 비용과 조건을 검증한 뒤 한 번 시작하고 한 번 반영한다. 시작한 작업은 조건·시간·효과 버전과 완료 시각을 고정한다. 중복 요청·동시 접속·재접속에도 재화 이중 차감·중복 수령·인력 이중 반환을 막고 기존 계정·초과 잔액·미수령 완료품을 보존한다.

렌더링은 화면 밖 오브젝트와 불필요한 갱신을 줄이고, 이미지와 오디오는 필요한 순서로 로드한다. 긴 운영 중 화면 이동·탐험·목록·컷신을 반복해 프레임·응답·로딩·메모리를 측정한다. 작은 화면의 한글·표·숫자·초점·선택 상태와 오류 복구도 같은 사용 흐름에서 확인한다.

QA는 인증, 파크와 동선, 자원과 정산, 공룡·부화·합성, 건설·기술·인력, 위인과 GP, 탐험, 스토리, 시즌·소셜·상점, 접근성·성능·저장·보안을 나눠 검증한다. 수치 모델 검산·단위 검사·저장 동시성 검사·전체 플레이·시각 검토는 각각의 증거를 남기고 완료 판정을 합치지 않는다. 구현 범위와 실제 실행 결과는 별도 기술 부록과 작업 기록이 관리한다.

| 검증 축 | 통과 조건 | 확인할 증거 |
| --- | --- | --- |
| 게임 규칙 | 담당 기획의 자원·해금·보유·비용·효과와 일치 | 규칙 대조와 수치 모델 검산 |
| 클라이언트와 API | 요청·응답·로딩·오류·복귀 상태 연결 | 화면에서 결과 수령까지 실제 흐름 |
| 정산과 저장 | 중복·동시 요청과 재접속에도 한 번 처리 | DB·서비스 검사와 계정 보존 결과 |
| 표현과 접근 | 한글·숫자·선택·초점·색상 보조 정보 식별 | 작은 화면·키보드·무음 상태의 시각 검토 |
| 장시간 성능 | 지속 운영과 화면 반복 이동 중 안정성 유지 | 프레임·로딩·응답·메모리 측정 |
| 완료 판정 | 검산·부분 기능·전체 플레이의 범위 명시 | 입력 버전·환경·명령·결과가 있는 실행 기록 |

## 9. 기획 갱신과 변경 검증

게임 기획은 주제별 담당 원천을 하나씩 둔다. 제작·서비스는 production-and-services.md, 사건과 관계는 스토리와 등장인물, 위인 GP·조건·능력은 위인 기획이 소유한다. 자원·건물·연구·DNA의 수치와 조건은 해당 기획을 읽고 가이드북의 편집 요약에 별도 설정을 만들지 않는다.

변경은 목적과 영향을 확인한 뒤 담당 원천을 먼저 고친다. 재료·확률·하한·수집 분모·인물 관계가 바뀌면 관련 표와 장면·화면·보상·진행 경로를 함께 대조한다. 승인된 내용만 편집 JSON에 반영하고 출처 지문을 갱신한 뒤 목차·본문·색인을 다시 생성한다.

가이드북 생성 후에는 제목·표·한글·쪽수·링크·색인·분할을 실제 출력에서 확인한다. 내용이 바뀐 페이지와 이전 승인 이미지의 지문을 구별하며, 출력의 문장 수정은 담당 원천에 되돌려 반영한다. 수치표 재생성이나 문서 생성만으로 게임 적용을 완료했다고 기록하지 않는다.

플레이 검증과 이관은 별도의 실행 기록으로 남긴다. 검산의 접속 가정과 작업 시간 합을 실제 플레이 기간으로 표시하지 않으며, 장기간 운영·확장과 여러 활동의 병행이라는 목표를 유지한다. 완성한 변경은 담당 문서·편집 요약·출력 검토의 버전을 맞춰 전달한다.

| 변경 단계 | 처리 기준 | 결과 |
| --- | --- | --- |
| 범위 확인 | 목적·영향·담당 원천 확인 | 하나의 변경 범위와 소유 문서 |
| 기획 반영 | 관련 조건·수치·관계·표를 함께 정리 | 담당 원천의 일관된 설계 기준 |
| 편집 갱신 | 승인 내용 요약과 source_sha256 갱신 | 원천과 연결된 JSON |
| 출력 검토 | 목차·본문·표·색인·링크와 페이지 이미지 확인 | 검토 범위와 원본 지문 기록 |
| 적용 검증 | 실제 구현·이관·플레이를 실행해 확인 | 환경과 결과가 있는 작업 기록 |
